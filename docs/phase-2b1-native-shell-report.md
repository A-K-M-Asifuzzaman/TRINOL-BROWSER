## Patch and verifier safety

The original clean source status and hashes were recorded before mutation.
Check-only application passed against the real pin before applying the patch.
`customization` in the manifest records ordered patch digests plus exact output
paths, Git modes and SHA-256 contents. A scratch index/object store computes
expected outputs without modifying the checkout. Pristine and applied modes
reject undeclared tracked or nonignored untracked source files, altered bytes,
mode changes, unsafe paths, symlinks and mismatched patches/pins. Application
refuses an already modified tree and never resets or cleans it.

The build runner retains exact revision, DEPS/tool and source checks. Customized
builds require the approved APFS UUID, one job, no GN generation and no active
compiler/browser. Existing external Siso cache, remote-execution prohibition,
exclusive lock and memory/storage guards remain in use. Depot_tools preserves
its existing tracked-file cleanliness policy: preexisting untracked bootstrap
caches were inventoried locally, not deleted or adopted as product source.

Git's outer patch-container whitespace rule permits unified-diff blank context
lines; the applicator separately enforces `git apply --whitespace=error-all`
against actual source additions. The initial patch commit failed foundation CI
only on context-line whitespace; the following fix passed. Shared history was
not rewritten.
